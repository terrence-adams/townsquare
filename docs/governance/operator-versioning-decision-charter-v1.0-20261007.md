**record_id:** `TS-OPERATOR-SCOPE-20261007-CHARTER-V1`  
**status:** operator direction; governs release-package preparation; it is not itself the Charter release or adoption event

> “since none of the prior versions were ever official, all of these version identifiers will be superseded . We will begin anew with an official 1.0 version once it is released. It will encapsulate all of the documents that make up the official TownSquare Charter.”

## Applied meaning

1. Earlier Doctrine, Rules of Engagement, object, lifecycle, receipt, resolver, protected-control, commentary, manifest, and adoption-packet version numbers are candidate/review provenance only. None is an official TownSquare version.
2. The first official release will be **TownSquare Charter v1.0**.
3. Charter v1.0 will encapsulate the complete governing set rather than adopting a mixed set of candidate version numbers.
4. Each encapsulated official component will begin at v1.0 under the Charter v1.0 package. Its candidate source identity and review history remain traceable but non-governing.
5. Release/adoption still requires exact final bytes, package and component hashes, scope, effective time, and a protected operator decision.
6. Charter release does not by itself authorize implementation binding acceptance, governed writes, deployment, archive actions, or closure of recovery/conformance findings.
