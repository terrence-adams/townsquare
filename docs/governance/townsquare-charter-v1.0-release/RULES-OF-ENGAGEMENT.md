# TownSquare Charter v1.0 — Rules of Engagement

**document_id:** `TS-CHARTER-1.0-ROE`
**charter_release:** `TS-CHARTER-1.0`
**status:** FINAL RELEASE BYTES — effective only through a separate attributable protected operator adoption record
**scope:** TownSquare governance

This component operationalizes the Charter Doctrine and adds no authority. `consequential action` means a state transition, acceptance, adoption, authority change, or other action declared consequential by an adopted profile. An informational append is not consequential merely because it is written.

1. **TSC-ROE-01 MUST — retrieve.** Before a consequential action, retrieve current record, adopted governance, dependency set, scope, criteria, and required evidence.
2. **TSC-ROE-02 MUST — preserve communication.** Correction, dispute, escalation, and failure reporting remain appendable; their publication alone grants no effect.
3. **TSC-ROE-03 MUST — evaluate effect.** Evaluate the effect of a record attempting a consequential action before that effect commits. Do not suppress the informational append path.
4. **TSC-ROE-04 MUST — resolve every dependency.** Resolve adoption, digest, scope, currency, revocation, and required acceptance independently for every governing artifact and binding. A package cannot adopt a member by inclusion.
5. **TSC-ROE-05 MUST — close independently.** The acceptor is outside the complete authorship set and cites criterion dispositions and evidence.
6. **TSC-ROE-06 MUST — preserve operator control.** Stop, question, override, accept, resume, direction, bootstrap, recovery, and authority change use the protected attributable control path and are never ordinarily gated.

## Conformance cases

| Case | Required result |
|---|---|
| informational correction while dependency resolution fails | append succeeds; no consequential effect is granted |
| record attempts CLOSED without independent acceptance | append may report the claim; CLOSED effect is denied/parked with reason |
| package names unadopted companion | consequential action is not effective |
| operator authority change before ordinary bootstrap | protected control succeeds and is audited |
| agent claims operator override | reject claim and audit |
